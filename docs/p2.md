# Fixed-state LOD and estimators

This page combines current fixed-state API contracts with dated P2 measurements. Production controller policies are specified in [the production protocol](production_campaign_20260927.md); current Theta execution and benchmarking are in [the operator guide](theta_fused_operator.md).

P2 provides reusable numerical modules on a fixed nested coarse/reference pair. It does not advance the reference epoch, choose ell, train regional dictionaries or run a production trajectory; these controllers belong to P3/P4.

## Run

```sh
python3 tools/run_fixed.py --config configs/p2/e1_fixed.json --output results/e1-fixed
python3 tools/run_fixed.py --config configs/p2/e2_fixed.json --output results/e2-fixed
build/alod_fixed --help
```

The output directory must be new. `run.json` contains the effective configuration, executable and member-table hashes, elapsed time and completion status. `state.json` contains the full complex solution block, per-vertex and per-element squared kernel indicators, reference strong indicators, selected member IDs, frozen scales, marks, PG/local residuals and localization evidence. Nonconvergence exits unsuccessfully and is recorded as a failed run, with details in `stderr.log`.

The strict JSON schema consists of the fields in `configs/p2/e1_fixed.json`. `level`, `gap` and `ell` define the coarse refinement level, additional uniform reference refinements and corrector radius. `graded` applies one deterministic local NVB refinement before constructing the reference. The C++ `LodSpace` API also accepts a supplied nested `RefineOutput`, including its nodal, element and DG embeddings. `maximum_nodes`, patch storage and dense-block limits bound this fixed-state probe. They do not replace production-scale resource scheduling.

`member_ids` selects rows from the frozen problem-specific table in `data/rhs/`; `training_ids` selects the subset allowed to drive marking. Both lists must contain distinct existing IDs. Nominal marking uses `[0]`; family marking normally uses `0..15`. Test and shift members can be evaluated but cannot enter `training_ids`. The library additionally distinguishes pure audit members. No build fingerprint or environment variable selects a marking policy.

## Explicit manuscript and archive definitions

Two independent configuration choices record differences discovered during migration:

| Field | Manuscript default | Archived compatibility |
|---|---|---|
| `interpolation` | `area`: element L2 projection, incident-area vertex average, zero Dirichlet rows | `arithmetic`: equal incident-element average |
| `riesz_patches` | `n2`: exactly the geometric vertex patch N²(z) | `archive`: global interpolation-support distance plus one expansion from each vertex star |

The arithmetic and area operators coincide on equal-area meshes and both reproduce coarse P1 functions. The graded counterexample in `tests/quasi_average_probe.cpp` distinguishes them. Both sparse-product and element-local assembly support the explicit policy. The older `build_quasi_interp` signature still defaults to arithmetic to preserve P1 SLOD baselines; the new P2 `LodSpace` defaults to area weighting.

The manuscript sets N⁰(z)={z}, so N(z) is the vertex star and N²(z) adds one shared-vertex element layer. The archived support calculation collects every coarse parent touched by fine nodal hats in an interpolation row. It can extend beyond the star; the archived implementation then adds another layer. On the tested E2 grids this gives N³(z), not N²(z). This is a real estimator difference even when the interpolation and LOD solution coincide. The archived policy reproduces its calculated support rule rather than hard-coding three layers. Every geometric coarse vertex, including Dirichlet vertices, remains a patch center in both policies.

All old/new fixed-grid equality claims use **arithmetic interpolation plus archived patches**. Manuscript-mode correctness is checked independently using explicit local kernel bases, positive energy matrices, geometric support checks and dense generalized spectra. Existing historical trajectories are evidence for the archived definitions; they are not relabelled as results of the manuscript definitions. Future controller comparisons must state both policies explicitly.

## Numerical contracts

`include/alod/lod.hpp` owns an immutable fixed space. Element correctors use the retained direct-Schur solver. For the real interpolation and complex-symmetric Helmholtz matrix, the test basis is the conjugate of the trial basis. Both primal and adjoint local equations are checked. The reduced system is `B_test* A B_trial`; one SparseLU factor solves a dense load block. Calls sharing one factor are sequential; independent local factors can run in parallel. State identities include meshes, boundary data, the actual embeddings/interpolation, wavenumber and ell.

`include/alod/estimator.hpp` defines the positive constrained patch Riesz solves for the residual `r=f-AU`, using energy `E=K+kappa² M`. The estimator is the sum of **local squared energy norms**, not the energy norm of the overlapping sum of representatives. Node mass is divided equally among that vertex's incident coarse triangles. Tests check each element allocation and total conservation.

The additive context retains batched Schur solves, sparse saddle solves for larger constraint sets, local factor reuse, deterministic reduction and duplicate-patch multiplicity. Full, empty and partial masks are tested. Selected representatives satisfy `Re(r* M_D r)=eta_D²`; a regional mask requires the complete patch to lie in the radius. This reusable primitive prepares P4 without implementing its enrichment controller.

`mark_family` freezes `max(||U_mu||_E,1e-12)` for each selected member. It marks mean normalized squared mass and adds the minimal stable-index supplement needed by the current worst normalized global member, retaining the archived `1e-14` supplement comparison. This guarantees the mean and worst-member bulk conditions within that comparison tolerance; it does not guarantee every member's bulk. Exact-solution norms and audit-only members do not enter the decision.

`reference_strong_residual` evaluates the embedded LOD solution on the entire reference mesh, with body, interior jump, Neumann and Robin terms from the preserved strong-residual kernel. Its result type and mesh differ from the coarse kernel estimator. It does not apply a regional AS mask. AFEM continues to estimate its own conforming FEM solution.

## Localization

`include/alod/localization.hpp` builds the adjoint defect `A* B_test` and its local-Riesz Gram action. Its denominator is the **uncorrected** coarse energy `P_H* E P_H`, restricted to free coarse coefficients. The conjugate primal defect has the same spectrum; the two sides are never added. Dense-kernel tests check this independently.

The compatibility spectrum path retains the archived small-space iteration and
four-vector matrix-free block Ritz iteration. Current normalized production
checks use the largest dense Hermitian eigenpair for small spaces and the block
Ritz method above the dense threshold (64 by default). The eigenvalue-relative
residual is `sqrt(r* M_H^-1 r) / max(1e-30,abs(lambda))`, with tolerance 1e-9 and
at most 750 iterations. The fixed-state/archived normalization remains explicitly
separate; historical fixtures keep their frozen tolerances. Large dense fallback
is disabled unless bounded explicitly. Current operator-image reuse, parallel
products and ordered Riesz gathers preserve the final fresh residual check.

The result is an approximation with convergence evidence, **not a certified
upper bound**. Warm starts are identity checked; adaptive controllers explicitly
transport them across valid mesh changes. The archived normalization by
`max(1,abs(lambda))` must not be described as the current normalized production
criterion. Nonconvergence is an explicit failure.

`localization_ratio` uses the nominal unnormalized kernel estimator. With positive eta it returns their ratio, including zero when Theta is zero. Zero eta gives `zero_denominator`, or `zero_defect` when both are zero, with no numeric ratio. The CLI also reports `nominal_missing` when member 0 was not evaluated. Fixed-space load scaling by `c` scales eta by `|c|` and divides the positive ratio by `|c|`. It does not prove that future adaptive trajectories are scale invariant.

## Validation and server profile

Six frozen archived-kernel fixtures cover E1/E2 uniform, graded and matrix-free Ritz states with 16 training loads. Normal builds only read the fixtures. `tools/build_p2_oracles.py` is a separate developer action requiring an explicitly supplied, freshly rebuilt portable archived library; it refuses to replace existing fixtures. `tools/compare_p2.py` checks complete solutions, patch geometry, node/element indicators, strong residuals, scales, exact marks and Theta. Expected marks independently evaluate the archived mean/minimal-supplement recipe on captured old indicators and solution energies; the full production controller is not executed in these fixed-state probes. The Theta comparison allows an absolute `1e-7` square-root roundoff floor near a vanishing defect; other floating values use `1e-10 + 1e-8*scale`. Integer identities and marks are exact.

Independent tests cover explicit kernel inverses, boundary vertices, local support, per-element conservation, additive identities, batch/scalar and thread agreement, member roles and permutation, worst-member supplements, two-sided spectra, warm starts, nonconvergence, ratio scaling and artifact failures. P0/P1 regressions remain required. Detailed results and source/fixture hashes are recorded in `provenance/p2_validation.json`.

`configs/p2/e2_medium.json` is a fixed H6/h10, ell=2, 16-RHS profile, not a full
E2 campaign. The current `tools/profile_fixed.py` does not pin CPUs or force
single-thread BLAS. `--cpus` records a descriptive list only; the shared runtime
helper controls requested OpenMP threads. The tool observes worker affinity and
CPU participation, process-group RSS/swap, available memory and kernel peak RSS.
Its default job ceilings are 4 GiB and 1800 seconds, with at least 80 GiB or 20%
physical memory reserved and a 1.5-times prelaunch allowance. Inspect existing
jobs before launching a bounded profile in a fresh directory through SSH/tmux.
The legacy `physical_cores` output is currently empty and is not a topology census.

The original P2 evidence used an explicitly pinned 16-core, single-thread-BLAS
measurement setup. That is a property of the historical measurement, not a
restriction of the current runtime. It establishes neither production-scale
capacity nor a universal speedup.
