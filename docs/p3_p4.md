# P3/P4 adaptive controllers and regional enrichment

P3/P4 implement the adaptive state machine, E1 controls, E2 regional training,
POD, inheritance and localization policies. Bounded tests are distinct from
new production experiments. The full campaigns listed below remain pending.

## Run and configuration

```sh
python3 tools/run_adaptive.py --config configs/adaptive/e1_smoke.json --output results/e1-adaptive
python3 tools/run_adaptive.py --config configs/adaptive/e2_smoke.json --output results/e2-adaptive
python3 tools/run_adaptive.py --config configs/adaptive/e2_forced_smoke.json --output results/e2-forced
```

The wrapper validates an exact JSON schema, materializes the frozen sample table
and calls `alod_run adaptive E1|E2`. It creates a new directory containing
`run.json`, `members.txt`, `events.jsonl` and `stderr.log`. The manifest stores
effective settings and content hashes without runtime paths. A completed
bounded run need not have completed the configured horizon. Failure preserves
the accepted journal prefix and last cursor. These files are not restart
checkpoints; serialization and resume belong to P5.

The common fixed-state fields are documented in [P2](p2.md). Additional fields:

| Field | Meaning |
|---|---|
| `method` | `ALOD` or family/nominal `AFEM` |
| `cycles`, `m_ref` | Coarse-update horizon and reference sweeps per update |
| `reference_theta` | Exactly `m_ref` positive fractions, used in sweep order |
| `state_limit` | Optional accepted-state bound; zero means the configured horizon |
| `minimum_gap` | Local reference reserve; E1 uses 2, E2 uses 0 |
| `ell_mode` | `lazy`, `every`, or non-promoting `fixed` |
| `maximum_ell`, `extra_checks` | Ell cap and explicitly scheduled check states |
| `force_promotions` | E2 diagnostic state IDs; empty in every production preset |
| `radius`, `rank_cap`, `inherit` | Complete-support AS region, working rank at most 24, dictionary transfer policy |
| `audit`, `emit_solution` | Synchronous exact errors for included members; optional complete nodal solutions |
| `maximum_patch_entries`, `maximum_dense_entries` | Positive storage ceilings, checked before core blocks are allocated |

`member_ids` controls evaluated members. `training_ids` alone controls growth and
marking; IDs are sorted for deterministic worst-member selection. All E1 control
presets evaluate the same 48 members and change only the explicit marking set
and method. Audit errors never select marks, stop ALOD, or change ell. The P3
audit contains exact norms/errors and computed energies; independent reference
FEM floors, fresh single-RHS retraining and checkpoint-only audits remain P5.

## Accepted-state semantics

An initial solve is state 0. Every coarse cycle performs one simultaneous coarse
and reference update followed by `m_ref-1` reference sweeps, each using the latest
accepted solution. A complete horizon has `1 + cycles*m_ref` states. Both marks
at the start of a coarse update use the same computed energy normalizers.
`coarse_cycle`, `reference_sweep`, `state_id`, `mesh_revision` and `ell_event_id`
are separate counters. Mid-cycle bounds retain the next phase and incomplete
cycle flag; they do not silently finish the cycle.

An archived detail matters for E1 reference-only sweeps: the old code closed the
reference mesh over a proposed coarse refinement, then discarded that coarse
proposal. The new controller preserves that reference closure. It seeds the
active region from every actually refined coarse element, including NVB
conformity closure, and expands by `ell+1` vertex-sharing rings. The accepted
coarse mesh stays fixed during those sweeps. `refine_pair` composes nodal,
element and DG embeddings and supplies the old-to-new reference injection.

The first embedding uses the extracted geometric implementation. Parent updates
use the extracted incremental search among descendants. One full geometric
embedding is still used for coarse warm-start transport; its large-grid cost
is a P6 optimization item.

## Localization policies

Lazy checks occur initially, at the bounded run's terminal state, at explicit
extra states, and after `2^ell` accepted states since the last check. Every
performed check resets that counter, including a keep decision. Reference-only
sweeps count. A terminal check in a deliberately shortened run can change its
last state relative to a longer run; prefix comparisons exclude that terminal
state. An unchecked state's `theta` is null. After an E1 promotion the old-ell
Theta remains only in its event and is not labelled as the new-ell Theta.

- E1: test `Theta/eta_H > 1.2` first; otherwise `Theta < 0.2` accepts the absolute
  criterion. Promote at most once at a scheduled state and solve again.
- E2: **lazy changes only when the check runs**. Its threshold remains
  `Theta/eta_H > 0.1`, using the final coupled nominal solution. Once triggered,
  train/compress/check again after each ell promotion on the same meshes until
  accepted or capped. Only the final solution becomes an accepted state.
- `every` preserves the E2 per-state checking policy as a separate preset.
- `fixed` observes on the lazy schedule but never promotes. Ell=3 controls
  therefore observe every eight accepted states plus initial/terminal states.

Positive Theta with zero eta requests promotion or records `ell_cap_reached`.
The zero/zero defect has no finite ratio. Nonconverged Ritz solves fail. Warm
blocks are explicitly injected through coarse nodal coordinates, restricted to
the new free nodes and rebound to the new checked identity; stale identities
are never passed through the fixed-state API. E1's main extra checks are 35/44.

## Regional method

`train_regional` selects only patches whose complete support lies in the radius.
An empty mask returns rank zero with `empty_region`; it never expands the
region. Selected patch multiplicities are retained. Raw kernel representatives
must satisfy quasi-interpolation and selected-support gates. The projected
trial columns can extend outside the region.

The current rank-zero training family fixes every target to
`max(1e-12, 0.1*eta_D(base))`. Inherited columns are checked first. Each growth
round chooses the largest budget ratio, reuses that evaluation's residual seed,
and adds at most two columns. The second seed uses the already deflated,
normalized current column in `M_D A phi`. Base energy projection and two-pass
Gram-Schmidt preserve the kernel representatives in matching coordinates.
Budget success, two successive gains below 1%, rank exhaustion, dependent seeds
and empty support have distinct exit reasons. Numerical gate failures remain
errors, not budget success.

Energy POD acts on normalized enrichment coordinates of the full-minus-base
solutions. Every candidate rank from 1 upward solves the actual coupled PG
system. Acceptance requires every training solution distance to be at most
`0.2*target` and its regional residual to be at most
`max(1.1*target, 1.03*full_residual)`. If no rank qualifies, the full dictionary
remains. `training_met` and `compression_accepted` are independent fields.

Global AOT solves `A* Z_raw = E Phi` on free reference DOFs with UMFPACK. It
projects tests off the base test space and retains the resulting nonzero
lower-left coupled block in a Schur solve. It does not assume that the raw
optimal-test identities survive that projection. The cache holds one factor,
keyed by actual sparse coordinates/values, coefficients and free DOFs. RHS or
ell alone can reuse the factor; every new RHS is solved. Cache counters and an
identity are recorded. No large-grid speedup is claimed.

Ell-only inheritance keeps compressed raw kernel representatives and rebuilds
their base projection, tests and targets. Mesh changes inject representatives
and repair with `M_D,new E_new P psi`. This changes directions and is not an
exact old-span preservation guarantee. Reset presets discard inherited input.

## Archive comparisons and scientific differences

E1's immutable prefix fixture checks six states across the state-4 promotion,
including exact marks, free-node counts, ell, all four smoke-member estimators
and nominal exact error. State 6 is excluded because this bounded run adds a
terminal check. Both archived interpolation and patch policies are selected.

The E2 archive contains a further discrepancy beyond P2's two policies: a cold
start first built two nominal raw-kernel Krylov vectors before base deflation,
then entered family training. This violates the plan's required `M_D A phi`
recurrence and empty-dictionary worst-budget selection. The new implementation
follows the plan. Its base targets and Theta match the archive; its enriched
solution is deliberately **not an archive-equivalent trajectory**. The frozen
initial-state comparison records a 0.01% proximity bound for eta and exact
error, separately from strict target/Theta checks. Unit tests independently
verify the prescribed coupled block algebra and POD acceptance inequalities.
This difference must remain visible when producing new E2 figures.

`test_p34` covers cursor counts, thresholds and zero denominators, partial/full/
empty AS masks, additive identities, raw/projected dictionary constraints,
coupled PG against a direct full block solve, POD distances, inheritance/reset,
mesh repair, and AOT invalidation for coefficients, values, pattern and free
DOFs. CLI tests cover complete/interrupted `m_ref=1/2/3`, forced 2-to-3-to-4
promotions, lazy/every schedules and four 48-member control contracts.

still require P5 restart persistence. The existing server policy remains:
launch from PowerShell/SSH in a fresh directory and tmux session, bind the whole
process to 16 distinct physical cores before OpenMP initialization, disable
OpenMP binding, use one BLAS thread, reserve at least 80 GiB or 20% of physical
memory, and monitor process-group RSS/swap. No long campaign is launched by
normal builds, tests or the configuration wrapper.
